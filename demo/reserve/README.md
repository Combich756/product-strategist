# «Резерв» · от сигнала до стратегии

Руководитель вымышленного сервиса резервного копирования выбирает одну итерацию после просадки проверок восстановления. [Запрос](request.md), [материалы](materials/) и [новый срез](updates/) входят в репозиторий. Пилот и счётчики синтетические. Публичные справки приведены в виде кратких конспектов со ссылками.

## Результаты живого прогона

- [Стратегия до сверки](results/01-before.md) предлагает проверить измерение Windows W44 и при подтверждении просадки испытать подсказку одного файла.
- [Затронутые выводы](results/02-impact.json) показывают, почему прежняя стратегия ушла в архив.
- [Стратегия после сверки](results/03-after.md) направляет итерацию на качество учёта Windows. Пользовательский сценарий и каналы сохраняются.
- [Проверка C2](results/04-audit.json) воспроизводит 70/200 и 100/200 в W44 по двум версиям XLSX.
- [Время и измерения](results/05-run.json), [сводка расходов](results/06-cost.json) и [журнал CLI](results/07-cli.jsonl) описывают фактическое выполнение.

Результаты получены в рабочей сессии Codex. Агент выбирал команды и сохранял проверенные черновики. Пауза и возобновление происходили через отдельные процессы Python и общее состояние кейса. Исследование и пересмотр дошли до этапа `decision`. Выбор владельца остаётся открытым. Отдельный Codex CLI в среде записи остановился на файловой системе. Точный model ID, токены и цена сессии недоступны. Работа на новых пользовательских данных требует отдельного прогона.

## Воспроизведение

Из корня проекта в окружении с зависимостями из `requirements.txt`.

```bash
python3 demo/reserve/replay.py --case reserve-demo
```

Скрипт использует [сохранённые артефакты](results/checkpoints/) и выполняет локальные проверки, паузу, замену XLSX и пересмотр. Отчёты сохраняются в `cases/reserve-demo/export/`. Для повторного запуска выберите новый ID.

Для живого прогона в Codex, Cursor или Qwen Code подготовьте только материалы.

```bash
python3 demo/reserve/replay.py --case reserve-live-2 --prepare
```

> Прочитай AGENTS.md и cases/reserve-live-2/request.md. Проведи кейс reserve-live-2 с начала до сохранения исследования. Используй материалы кейса. После исследования поставь кейс на паузу и перечисли, чего не хватает для выбора.

Затем можно продолжить в новом чате.

> Продолжи кейс reserve-live-2. Восстанови сохранённое исследование, сними паузу и предложи варианты и стратегию. Оставь решение владельцу.

После получения первой стратегии скопируйте файлы из `updates/` в `materials/` кейса и попросите агента обновить снимок исходной таблицы через `ingest --replaces`, пересчитать выводы и вынести обновлённое решение на выбор. Время, помощь человека и измеренный расход модели фиксируйте через `log`.
