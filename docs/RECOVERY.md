# Продолжение после сбоя

В проекте три разных состояния результата:

| Где результат | Что это означает |
|---|---|
| Текст в чате агента | Сохранение файла ещё не подтверждено |
| JSON в `cases/<кейс>/drafts/` | Есть черновик; он может быть неполным или непроверенным |
| Этап в `status` / `report` | Артефакт проверен CLI и записан в SQLite |

`check` подтверждает структуру, допустимые ссылки и объявленные расчёты. Он не устанавливает причинность, полноту цитирования всех мыслей и экономическую обоснованность. `save` сохраняет этап, а `decide` отдельно записывает явный выбор владельца.

## После тайм-аута

1. В обычном терминале выполните `python3 -m strategist recover qwen-check`.
2. Если кейс приостановлен, сначала `python3 -m strategist resume qwen-check`, затем повторите `recover`.
3. Найдите подходящий файл следующего этапа. Для него выполните, например, `python3 -m strategist check qwen-check strategy cases/qwen-check/drafts/strategy.json`.
4. Прочитайте файл. Для русского текста: `python3 -m json.tool --no-ensure-ascii cases/qwen-check/drafts/strategy.json`.
5. Проверьте смысл и выполните предложенную `save` с текущим `--expect`. При изменении ревизии заново прочитайте состояние. После успешного сохранения откройте `report`.

Все команды проверки локальны и не требуют API. `recover` ничего не записывает и не выполняет выведенные команды. Одновременно подходящих файлов может быть несколько: выбор версии остаётся за агентом и человеком. Черновик решения не приводит к автоматическому `decide`.

Частичный JSON можно исправить по уже подготовленному результату; генерировать всю стратегию повторно не обязательно. Файлы должны называться `brief.json`, `research-v2.json`, `options.json`, `strategy.json` и т. п. Для другого имени используйте `check` с явным этапом. Символические ссылки и черновики больше 1 МБ не обрабатываются восстановлением.

## Числовые доказательства

```bash
python3 -m strategist rates qwen-check S002 --by week platform --numerator connected_48h --denominator eligible_orders --evidence
python3 -m strategist cells qwen-check S002 --rows 3 5 --columns eligible_orders
```

Первый вызов возвращает `rate_checks` и `refs` для долей. Второй возвращает `cell_checks` и ссылки на значения 100 и 220. Включите нужные поля в утверждение исследования. Для доли вставьте в `text` ссылку `{{rate:1}}` с номером нужной проверки. Если старый черновик содержит `48/80 (99%)`, а пересчёт дал 60%, `check` покажет расхождение. Проверки относятся к конкретному снимку, а после его замены вывод пересматривается.

Старые сохранённые кейсы не удаляются и не мигрируют автоматически. Новые требования применяются при повторном сохранении исследования. Если в старом JSON не было проверок чисел, добавьте их перед сохранением через `reopen`.

## Учёт задержки

```bash
python3 -m strategist log qwen-check --kind model --label "API: запрос завершился тайм-аутом" --seconds 484 --outcome timeout --attempts 1
python3 -m strategist cost qwen-check
```

Указывайте только наблюдавшиеся секунды и попытки. Без показаний токены и цена неизвестны. Для исправлений человеком используйте `--kind human`. `log` изменяет ревизию, поэтому обновляйте `--expect` после записи. Журнал не является полным журналом запросов IDE: временной промежуток между двумя сохранениями может включать перерывы.
