# Независимая проверка стратегии

Перед показом владельцу ведущий агент проверяет черновик командой `check`, сохраняет этап `strategy` и запрашивает независимое чтение. Проверяющий оценивает выбранное действие, допустимость обещаний, пороги и план проверки. Итогом служит вердикт с привязкой к версии. Утверждение решения и его обязательств по-прежнему выполняет владелец через ведущего агента.

## Обычный запуск

В открытом проекте достаточно попросить агента «Проверь готовую стратегию кейса demo перед показом владельцу». В Qwen Code ведущий агент передаёт пакет профилю `strategy-reviewer`, у которого из инструментов есть только `read_file`. В Codex он выбирает `strategy_reviewer` и передаёт пакет текстом в новый контекст без истории автора. Права файловой песочницы Codex задаёт среда запуска. Если среда предоставляет только обычные чаты, откройте новый сеанс только для чтения с тем же пакетом. Ведущий агент регистрирует полученный JSON. [Конфигурация субагентов Codex](https://developers.openai.com/codex/subagents/)

Оба режима `qwen-run` автоматически отправляют независимый запрос без инструментов после сохранения стратегии при достаточном бюджете. Команда завершает запуск при замечаниях и выдаёт их основному агенту. Режим проведения исследования можно выбрать отдельно. [Учёт расхода](BUDGET.md)

## Что читает проверяющий

Пакет содержит вопрос и ограничения, стратегию, варианты, пересчитанные метрики с доступными порогами, пробелы исследования и факты или гипотезы, на которые опираются варианты, стратегия и метрики. Для цитат приложены полные строки снимков с исходными номерами. У таблиц добавлены заголовки. В пакет попадают только связанные выдержки. Историческое утверждение о прежнем решении требует собственного основания. Когда текущий пакет его не содержит, проверяющий может указать этот пробел.

## Команды ведущего агента

Пример для кейса `demo` с сохранённой стратегией.

```bash
python3 -m strategist review-strategy demo --begin
```

При `dispatch: true` отправьте единственному проверяющему только объект `packet`. Его поле `instructions` содержит инструкции и формат ответа. В Qwen Code пакет можно передать отдельным файлом. Следующая команда читает то же назначение.

```bash
review_dir=$(mktemp -d cases/demo/review.XXXXXX)
python3 -m strategist review-strategy demo --packet > "$review_dir/packet.json"
```

При `dispatch: false` используйте сохранённый результат или дождитесь уже назначенного проверяющего. Текущий статус доступен через `review-strategy demo`, `status` и `recover`. Ведущий агент сохраняет ответ в `result.json` в той же временной папке и регистрирует его.

```bash
python3 -m strategist review-strategy demo --record "$review_dir/result.json"
python3 -m strategist report demo --for-owner
```

| Вердикт | Что делает основной агент |
|---|---|
| `clear` | Показывает проверенную рекомендацию и спрашивает о выборе. |
| `changes_requested` | Сверяет указанное поле, цитату и основание. Применяет обоснованную правку через `reopen strategy`, `check` и `save`. Если возражение спорное, показывает владельцу предмет разногласия. |
| `inconclusive` | Называет недостающий материал и объясняет, как он влияет на решение. |

В каждом замечании обязательны дословная цитата, поле стратегии, доступные основания, объяснение расхождения и конкретная правка. CLI проверяет наличие цитаты и оснований. За смысл возражения отвечает рецензент, его вывод тоже можно оспорить. Рабочий `report` доступен на любом этапе и показывает статус проверки. `report --for-owner` выдаёт готовую рекомендацию только при `clear`. Во время пересмотра состояние ранее утверждённого решения и его обязательств доступно через `followup`.

## Пауза и сбои

Версия зависит от кейса, содержания стратегии и её оснований. Пауза, повторная команда или запись времени сохраняют назначение. Повторная запись того же вердикта безопасна. Ответ на прежнее назначение или изменившуюся версию отклоняется. Старая стратегия из сохранённого кейса по умолчанию имеет статус `pending`.

Если соединение оборвалось, сначала запросите `review-strategy demo`. При `in_progress` продолжите текущее назначение или зарегистрируйте уже полученный ответ. Если сеанс потерян и результата нет, ведущий агент может закрыть именно это назначение командой `review-strategy demo --interrupt TICKET` и повторить запуск. При сетевом сбое в `qwen-run` результат запроса и резерв токенов видны в учёте. Повтор требует нового запуска. Если ответ уже получен во время паузы, `recover` показывает файл в `reviews/` и команду регистрации. Выполните её после `resume` без повторного вызова модели.

## Проверка на «ТараВозврате»

Три копии одного синтетического кейса прошли формальную команду `check`. В независимых сеансах Codex каждый проверяющий видел одну версию, без метки варианта и эталона.

| Версия | Результат |
|---|---|
| Подставлено O2 (расширение) при плане сохранить две точки | Найдено противоречие. Реестр даёт 79 из 100 при требуемых 80%. |
| В сообщение добавлен доказанный рост возвратов от напоминаний | Найдено неподтверждённое обещание. Паспорт указывает, что эффект не измерялся. |
| Исходная стратегия | Обнаружены двусмысленное описание прежнего расширения и неполное правило пересмотра, в частности для 79,5%. |
| Исправлены два замечания к исходной версии | Четвёртый независимый сеанс вернул `clear`. Отчёт для владельца открылся. |

В исходной выгрузке действительно было 82%. Реализация расширения до двенадцати точек из материалов не следует. Варианты с внесёнными ошибками сохранили исходные недостатки, но проверяющие в тех двух сеансах указали только внесённые ошибки. Эти четыре чтения проверяют работу механизма на одном кейсе. Денежная стоимость, экономия времени и полнота обнаружения ошибок на других кейсах требуют отдельного измерения.
