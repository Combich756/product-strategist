# Токенный бюджет этапов

`budget` читает состояние кейса и показывает, поместится ли следующий этап в оставшийся бюджет. Для этого достаточно Python. `qwen-run` использует тот же расчёт и запускает установленный Qwen Code в терминальном режиме без интерфейса. Для запроса модели нужен Cloudflare Workers AI с доступным токеном и квотой. [Qwen Code Headless](https://qwenlm.github.io/qwen-code-docs/en/users/features/headless/) · [Workers AI Chat Completions](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/)

## Запуск

Из корня проекта проверьте существующий кейс. Числа в примере задают пробный бюджет и оценку этапа.

```bash
python3 -m strategist budget qwen-launch --limit 200000 --estimate 65000 --reserve 10000
```

Если `decision` равно `start`, запустите Qwen. Подставьте свой Account ID из Cloudflare. Скрипт запросит токен скрытым вводом. Для скриптовой среды токен можно передать через `STRATEGIST_CF_TOKEN`.

```bash
python3 -m strategist qwen-run qwen-launch --limit 200000 --estimate 65000 \
  --reserve 10000 --account ВАШ_ACCOUNT_ID
```

После сохранения этапа запуск пересчитает бюджет. Он откроет отдельный сеанс для следующего этапа, если прогноз помещается в остаток. На `decision` управление возвращается владельцу. При `insufficient` проверьте `shortfall_tokens`. При `needs_estimate` задайте оценку через `--estimate`. Явная оценка применяется к этапам этого запуска. Без неё CLI берёт 90-й перцентиль успешных измеренных запусков того же этапа и модели из кейсов в `--root`.

## Как считается расход

- `--limit` действует на суммарные входные и выходные токены запусков `qwen-run` этого кейса. Расход сохраняется в SQLite и учитывается при следующем запуске. Ручные записи `log` и статистика обычных чатов показаны отдельно.
- Перед каждым запросом локальный шлюз сравнивает остаток с резервом на оценённый вход и максимальный выход. Вход оценивается по размеру сериализованного UTF-8-запроса с запасом на форматирование. `--max-output-tokens` ограничивает выход одного запроса, по умолчанию 8192. Шлюз принимает текстовые запросы Chat Completions.
- Шлюз получает полный ответ Workers AI, записывает `usage.prompt_tokens` и `usage.completion_tokens` и передаёт ответ Qwen Code. Фактическая токенизация входа на стороне провайдера может отличаться от оценки. Следующий запрос проверяется уже по измеренному расходу.
- Если ответ пришёл без `usage` или связь оборвалась после отправки, резерв остаётся в `unmeasured_reserved_tokens`. Явный отказ при допуске запроса, включая HTTP 429, отражается в `rejected_requests`. Запуск останавливается после ответа с ошибкой. Внутренний токенный бюджет и квота Cloudflare в Neurons учитываются раздельно.

```bash
python3 -m strategist cost qwen-launch --summary
python3 -m strategist status qwen-launch
python3 -m strategist recover qwen-launch
```

В `cost` поле `qwen_usage.by_stage` показывает расход по этапам. При остановке во время этапа `recover` проверит черновики на диске. При новом запуске `qwen-run` сначала проверит бюджет и снимет паузу, если следующий этап допущен. Токен провайдера передаётся Cloudflare из процесса запуска. Qwen Code получает отдельный ключ для локального шлюза на `127.0.0.1`.
