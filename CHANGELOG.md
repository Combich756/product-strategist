# Изменения

## 2026-11-12

- Добавлена локальная проверка ключей и контактов. Для сохранения снимка с замаскированными контактами требуется подтверждение в терминале. `qwen-run` проверяет запрос перед отправкой в Workers AI.
- Добавлены `budget` и `qwen-run`. Запуск Qwen проверяет прогноз до следующего чекпоинта и остаток перед запросом. Фактические токены Workers AI учитываются по этапам.
- Добавлены карточки диагностики падения метрики, выбора сегмента и оценки окупаемости пилота. Агент открывает карточку по вопросу исследования.

## 2026-11-11

- Добавлены `context --compact`, загрузка отдельного этапа через `--stage` и `cost --summary` с суммами известных токенов.
- Проведён живой кейс «Резерв» до стратегии и пересмотра после замены XLSX. В репозитории есть исходные материалы, отчёты, журнал, замеры и сценарий воспроизведения.
- Кейс сохраняет момент и пояс анализа, бриф фиксирует периоды сравнения. Снимок источника хранит указанные даты среза, охвата данных и действия условий. `claim --revision` показывает временной контекст архивного вывода.
- `ingest --file` принимает PDF с текстовым слоем, DOCX и XLSX. Парсеры устанавливаются из `requirements.txt`.
- Для PDF сохранены номера страниц. Для XLSX сохраняются лист и номера исходных строк. `cells`, `rates` и проверка выводов используют снимок выбранного листа.

## 2026-11-10

- Добавлены профиль `materials-researcher` для Qwen Code и переносимый контракт делегирования.
- Сбор материалов выполняется в отдельном контексте; в основной возвращаются сводка и ссылки на подробные результаты.
- Результат использует существующие проверки исследования без изменения состояния кейса субагентом.
- Выполнен реальный запуск отдельного помощника в рабочей сессии; сохранены исходные результаты, проверка и замечание главного агента. Qwen Code и экономия расходов этим прогоном не проверялись.

## 2026-11-09

- Числовые выводы со ссылками на CSV/TSV требуют проверок значений или долей, включая гипотезы.
- `rates --evidence` и `cells` выдают готовые ссылки и проверки по неизменяемому снимку.
- `check` проверяет черновик без записи; `recover` находит незавершённый этап и подходящий файл после сбоя.
- Повторные JSON-поля отклоняются; сохранение фиксирует хеш артефакта.
- В `log` добавлены исход запроса и количество попыток, а отсутствие учёта явно отмечается в `cost`.
- Исправлены демопримеры, правила экономики оплаченных заказов, сверки исходной когорты и маркировки оценок.
- Добавлены тесты восстановления, документация частичного живого прогона и GitHub Actions.

Старые кейсы остаются читаемыми; новые требования к числовым доказательствам применяются при повторном сохранении исследования. Качество стратегии и скорость API требуют отдельной живой проверки.
